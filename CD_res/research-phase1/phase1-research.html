Part I · Decision areas · ranks 01–06

Six decision areas, one build order

The research voted with evidence: fix the trust store first, then diff, score, card, prompt, shim.

  1. 06

    Security debt · fix firstPhase 0 bugs: the store records approval as truth

    2 pathsin shipped Phase 0 code that let a backdoored version become "known-clean"

    • review.rs:43-48 records the version as known-clean before any verdict runs.
    • store.rs silently overwrites the stored integrity when the same (name, version) is seen again.
    • npm.rs:132 sorts the version list lexically; the registry orders by semver precedence, and lexical sort is wrong for 10.x vs 9.x.
    • Consequence: review a poisoned release, press approve, and your store now blesses it. The fix is to record verified not approved, gate writes on verdict, and fail on integrity change.
  2. 01

    Diff engineFiles first, lines later

    similar 3.1.2 + walkdir 2.5.0the entire v1 dependency bill for diffing

    • File-level ops first: a path-keyed BTreeMap merge, not an edit script. Every 2018-2026 npm incident shows up at the file-op level without any line diffing.
    • Binary detection before any line diff, git's rule: NUL byte in the first 8 KiB. "Changed but unreadable" is a first-class signal, never a skip; flatmap-stream hid in a minified file, the TanStack worm was a 2.3 MB obfuscated new file.
    • Deadline and size caps on TextDiff (Myers, O((N+M)D)); oversized input degrades to OpaqueChanged instead of an OOM. Never Algorithm::Lcs.
    • similar's inline refinement is documented "not defined, will change": use it for display only, never score on it.
    • The old diff/difference crates are frozen since 2018-2022; diffy is apply-oriented. Not contenders.
  3. 02

    Verdict heuristicsAdditive weights, hard latches

    5 BLOCK latchesscore can't override; everything else is a weighted sum to 100

    • Weights derived from the incident corpus: obfuscation 45 · new script 40 · exec/net 35 · maintainer 30 · dormant 30 · version burst 25 · new binary 25 · new dep 10 (dep cap 30). Soft cap 100, monotonic, offline-deterministic.
    • Bands: LOW 0–19 · MEDIUM 20–49 · HIGH 50+. BLOCK is a latch: revocation, new install script vs clean baseline, non-registry dependency, provenance regression, integrity failure.
    • Script presence alone cannot block. 2.2% of npm packages ship lifecycle scripts, 81% of malware uses them; keyword matching alone misfires on 11/74 legit packages.
    • Output is a typed Verdict enum feeding the D7 JSON schema, with per-signal evidence and a registry_snapshot_at timestamp so the same input forever yields the same verdict.
  4. 03

    Card + promptThe human says no by default

    null defaultno implicit allow: bare Enter re-prompts, everything else denies

    • comfy-table 8.0.0 (2026-08-05). The adversarial pass caught the original pin: 7.2.2 was stale and its API is gone. load_preset and the modifiers module were removed; presets are now TableStyle constants loaded via load_style.
    • Color via owo-colors 4.3.0 + supports-colors; honors NO_COLOR and non-TTY.
    • No prompt crate. inquire and dialoguer are Enter-to-submit; neither does single-key [a]/[h]/[d]. Hand-roll a single-key reader on crossterm, which is already in the tree.
    • Fail-closed contract: prompt only when stdin.is_terminal() and TERM != dumb; h/Ctrl+C/Ctrl+D/EOF all exit non-zero; only a reaches the install.
    • Inverts the anti-patterns: npx's (y) default-allow and npq's 15s auto-continue are the models to avoid; socket's --no-interactive = cancel is the model to copy.
  5. 04

    Node shimZero scripts, real binaries

    0 postinstallworks under --ignore-scripts, which the whole product depends on

    • @blueline/cli is a launcher with exact-pinned optionalDependencies on @blueline/binary-{linux,darwin,win32}-{x64,arm64}[-gnu|-musl]. This is the esbuild/oxc/biome pattern; a postinstall downloader would be blocked by --ignore-scripts and is a footgun.
    • Launcher resolves via a platform map + require.resolve, honors a BLUELINE_BINARY env override, and spawnSyncs the binary with stdio: "inherit" and verbatim status passthrough.
    • npm's programmatic API is gone (removed in v8.0.0). Install runs by spawning the CLI via npm_execpath. The original report cited npm/cli#6407 for this; the adversarial pass proved the citation fabricated, corrected to npm/npm#11130.
    • Release: GitHub Actions matrix, cargo-zigbuild for linux gnu/musl, native runners elsewhere, platform packages published before the metapackage, smoke test on win/ubuntu/alpine. cargo install coexists cleanly.
  6. 05

    Baseline resolutionLast known-clean, semver-ordered

    4 sourceslockfile → store → registry → first sighting, in that order

    • Priority: lockfile packages map (binds name+version+integrity, path-stable across hoisting and pnpm symlinks), then the known_clean store, then the registry version list ordered by semver precedence, then first sighting with a loud no_known_clean_baseline flag.
    • The registry hides unpublished versions from versions but the packument time entries linger; ordering by publish time is unreliable.
    • Neutral first sighting is defensible: the ecosystem warns rather than blocks on unknown-new, and ua-parser-js shows the high-risk event is a new version of a known package, not the first install.
    • "Known-clean" must be a cache of what was verified, never a judgment: re-verify integrity at consumption time.

What the diff should have caught

Every major npm supply-chain incident mapped to the signal that would have flagged it, against the proposed v1 rule set.

The rule set is not invented from vibes; it is reverse-engineered from what these attacks actually looked like.

Provenance is a display, not a blessing

The TanStack worm shipped with valid SLSA provenance and still installed malware. v1 surfaces attestations and never trusts them; the diff and the script latch are where the decision lives.

Part IV · Method

Raw material & caveats

How the five reports were produced, and where to distrust them anyway.

How the research ran

  • Five subagents in parallel, one per decision area, each owning exactly one output file under CD_res/research-phase1/.
  • Each claim grounded in a fetched primary source: crates.io and docs.rs for crates, GitHub repos and release notes for tools, npm registry behavior against the live packument, and incident postmortems against the vendors that wrote them.
  • An adversarial verifier then attacked the load-bearing claims, fetching the same sources. Refuted claims were corrected in the reports and passed a confirmation pass. Status GREEN.

Caveats

  • Reverse-dependency counts drift: the report says 1,147, one live check read 1,020. These are point-in-time numbers, cosmetic either way.
  • nan-crate activity dates ("maintained 2026") were framed from release history, which for walkdir is quiet since 2024-03-01.
  • Vendor numbers (Socket's formula, Snyk's priority score) are published reference models, not evidence about live deployments.
  • Nothing here covers Phases 2-5: revocation caches, provenance verification, hosted recall, or the ML verdict model. Scope is Phase 1 only.

ADiff enginediff-engine.md

Dependenciesthe whole bill

similar 3.1.2 with the inline feature only, plus walkdir 2.5.0. The old diff and difference crates are frozen; diffy is apply-oriented and unnecessary.

Output shapetyped Delta

  • Per-path operations from a BTreeMap merge, not an edit script; hunks are a render-time concern.
  • Binary and oversized files become OpaqueChanged: present in the delta, unreadable to the diff, never silently skipped.
  • Empty delta between distinct versions is a note, not an error; missing baseline is an error, never a fake empty diff.

BVerdict heuristicsverdict-heuristics.md

Scoring modelv1 weights

Weighted additive sum with per-signal soft caps, a global cap of 100, and monotonic risk-only movement. Five hard latches bypass the score entirely.

Where the weights come fromevidence

  • Obfuscation and new-script signals derive from event-stream, node-ipc, eslint-scope, keyv, and TanStack.
  • Dormancy and version-burst signals derive from ua-parser-js and coa/rc.
  • False-positive calibration: legitimate postinstall in sharp, esbuild, core-js; keyword matching alone misfires on 11 of 74 samples.

CCard + interactive promptcard-and-prompt.md

Dependenciestwo crates

comfy-table 8.0.0 (default features) and owo-colors 4.3.0 with supports-colors. No prompt crate; single-key reading rides crossterm.

The interactive contractfail closed

  • Prompt only on a real TTY with a sane TERM; piped and dumb-terminal runs emit the JSON verdict instead.
  • Bare Enter re-prompts, unknown keys re-prompt, h and Ctrl+C and Ctrl+D and EOF all exit non-zero.
  • Only an explicit a proceeds to the install. There is no auto-allow and no timeout that advances to allow.

DNode shim + releasenode-shim.md

Package layoutzero-scripts

Metapackage with exact logical optionalDependencies on eight platform packages. No install.js, no postinstall, no repair fallback. The pattern is proven by esbuild, oxc, and biome.

Execution chainshim to install

  • Launcher: platform map + require.resolve, BLUELINE_BINARY override, spawnSync with inherited stdio, verbatim exit code.
  • Approve path spawns the real npm through npm_execpath with --ignore-scripts; stdio and signal passthrough keep the TTY and the contract intact.
  • npm CLI was the supported way to do this since the programmatic API was removed in v8.0.0.

Sourcesprimary

  • github.com/npm/npm/pull/11130 · npm CLI docs (npm-install, npm exec) · npm scripts docs
  • esbuild lib/main.js and install layout · oxc and biome package layout and release workflows
  • cargo-zigbuild docs · GitHub Actions release work
EBaseline resolutionbaseline-resolution.md

Resolution algorithmpriority order

Lockfile v3 packages map, then the known-clean store, then the registry list ordered by semver precedence, then first sighting with a machine-readable no-baseline flag and a neutral verdict.

Anti-poisoning rulesfixes Phase 0

  • Only a LOW verdict writes to known-clean; witnessed but unjudged versions are recorded as verified, not clean.
  • Integrity changes on a stored version fail the review instead of silently overwriting.
  • The registry version ordering bug (lexical vs semver) is corrected with npm's resolutor behavior as the reference.
